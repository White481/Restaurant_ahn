## คนที่ 1 — ภาพรวม + ER Diagram (4 นาที)

**[จอ: หน้าเว็บลูกค้า]**
> "สวัสดีครับ กลุ่ม 10 ทำระบบ **All About Food!** ระบบจัดการออเดอร์ร้านอาหาร
> ปัญหาที่แก้คือร้านเล็กจดออเดอร์ด้วยกระดาษ ครัวอ่านลายมือไม่ออก และไม่รู้ยอดขายรายวัน
> ระบบเราให้ลูกค้าสแกน QR ที่โต๊ะสั่งเอง ออเดอร์เด้งเข้าจอครัวทันที แล้วแต่ละตำแหน่งในร้านจัดการเฉพาะงานของตัวเอง"

> "ใช้ React ทำหน้าเว็บ, Node.js + Express ทำ API และ MySQL เป็นฐานข้อมูล"

**[จอ: `docs/er-diagram.png`]**
> "ฐานข้อมูลมี **7 entities, 6 relationships** แบ่งได้ 3 กลุ่ม
> - **คน:** `staff` เก็บพนักงานพร้อมบัญชี login และ role เป็น ENUM 4 แบบ
> - **ร้าน:** `dining_table` เก็บโต๊ะและสถานะ ว่าง / เปิดอยู่ / ปิดใช้งาน
> - **อาหารและออเดอร์:** `menu_item`, `ingredient`, `menu_item_ingredient`, `orders`, `order_item`"

> "มีความสัมพันธ์ M:N 2 จุด
> - **ออเดอร์กับเมนู:** หนึ่งออเดอร์มีหลายเมนู หนึ่งเมนูอยู่ในหลายออเดอร์ จึงมีตารางกลาง `order_item` ซึ่งเก็บ `subtotal` ไว้ด้วย ถ้าเปลี่ยนราคาเมนูทีหลัง บิลเก่าไม่เปลี่ยน
> - **เมนูกับวัตถุดิบ:** ผ่าน `menu_item_ingredient` ซึ่งเป็นสูตรอาหาร ใช้ composite primary key `(menu_item_id, ingredient_id)`"

> "ตาราง `orders` มี FK ไป `staff` 2 เส้น คือคนรับออเดอร์ (`staff_id`) กับคนรับเงิน (`paid_by`) ชื่อคนรับเงินจึงไปขึ้นในใบเสร็จได้"

**[จอ: Workbench `SHOW CREATE TABLE orders;`]**
> "schema ใน MySQL ตรงกับ ER ทุกตาราง เห็น FK ตรงนี้ เมนูที่เคยถูกสั่งแล้วใช้ `ON DELETE RESTRICT` ลบไม่ได้ เพื่อปกป้องประวัติการขาย"

> "เดิมเราออกแบบไว้ 11 ตาราง แต่ตัดตารางที่ไม่ได้ใช้จริงออกและรวมตาราง 1:1 เหลือ 7 เพื่อให้ทุกตารางมีหน้าที่ชัดเจน ต่อไปคนที่ 2 จะ demo ระบบจริงครับ"

## คนที่ 2 — Demo สด + Roles + CRUD (6 นาที)

**[จอ: แท็บลูกค้า `/?table=2`]**
> "สมมติลูกค้าเข้าร้านมานั่งโต๊ะ 2 สแกน QR แล้วเลือกเมนู ข้าวผัดกะเพรา 2 จาน กดสั่ง…"
→ กดสั่ง ขึ้นว่า **"โต๊ะนี้ยังไม่เปิด"**
> "สั่งไม่ได้ครับ เพราะพนักงานยังไม่ได้เปิดโต๊ะ ระบบกันคนถ่ายรูป QR กลับไปสั่งจากบ้าน"

**[จอ: แท็บ waiter → เมนู "โต๊ะ"]** กด **เปิดโต๊ะ** ที่ T2
> "พนักงานเสิร์ฟเปิดโต๊ะให้ ตอนนี้ลูกค้าสั่งได้แล้ว"
→ กลับแท็บลูกค้า กดสั่งอีกครั้ง (วิธีจ่ายเลือก QR ให้เห็นรูปพร้อมเพย์) → ไปหน้าติดตามสถานะ

**[จอ: แท็บ chef]** (login chef ในแท็บใหม่ หรือสลับบัญชี)
> "พ่อครัวเห็นออเดอร์ใหม่ทันที กดได้แค่ 'เริ่มทำ' กับ 'ทำเสร็จ' ไม่มีปุ่มยกเลิกหรือรับเงิน และไม่มีเมนูโต๊ะหรือแดชบอร์ด"
→ เริ่มทำ → ทำเสร็จ (หน้าลูกค้าอัปเดตเอง)

**[จอ: แท็บ waiter]** กด **เสิร์ฟแล้ว**
> "พนักงานเสิร์ฟกดเสิร์ฟได้ แต่ถ้าลองข้ามขั้นหรือกด 'เริ่มทำ' จะไม่มีสิทธิ์ ระบบให้เดินสถานะทีละขั้นเท่านั้น"

**[จอ: แท็บ cashier]** กด **ชำระเงิน** → เงินสด รับ 200 → เงินทอนขึ้นเอง → ใบเสร็จ
> "แคชเชียร์ทำได้แค่รับเงิน ใบเสร็จมีชื่อแคชเชียร์ คิด VAT 7% และแสดงเงินทอน"

**[จอ: `backend/src/config/permissions.js`]**
> "สิทธิ์ทั้งหมดอยู่ในไฟล์นี้ไฟล์เดียว มี 4 role คือ admin, chef, waiter, cashier บวกลูกค้าที่ไม่ต้อง login
> ตัวที่บังคับจริงคือ backend ตรวจ role จาก JWT ทุก request ถ้ายิง API ตรงโดยไม่ผ่านหน้าเว็บก็ได้ 403 ส่วนหน้าเว็บแค่ซ่อนปุ่ม"

**[จอ: แท็บ admin → เมนู]** CRUD เมนู (เร็วๆ)
> "admin จัดการเมนูได้ครบ CRUD"
→ **เพิ่ม** "ข้าวไข่เจียว" 45 → **แก้ไข** เป็น 50 → **ซ่อน** (หายจากหน้าลูกค้า) → **ลบ**
→ ลองลบ "ข้าวผัดกะเพรา" → ขึ้นว่า "เคยถูกสั่งแล้ว จึงซ่อนไว้แทนการลบ"
> "ทุกครั้งที่กด ข้อมูลใน MySQL เปลี่ยนทันที (สลับไป Workbench `SELECT * FROM menu_item;` ให้ดู)
> ถ้ากรอกราคาติดลบ ระบบไม่บันทึกและแจ้ง error"

> "ปิดท้ายด้วย UI: สลับภาษาไทย/อังกฤษ โหมดมืด และใช้บนมือถือได้ ต่อไปคนที่ 3 จะอธิบายสิ่งที่เกิดขึ้นหลังบ้านครับ"

## คนที่ 3 — Trigger + Stored procedure + Security (5 นาที)

**[จอ: `database/triggers.sql`]**
> "เมื่อกี้มีหลายอย่างเกิดขึ้นเองในฐานข้อมูล ผ่าน trigger 3 ตัว"

**Trigger ตัวที่ 2: โต๊ะยังไม่เปิด** (โต๊ะ 2 ถูกปิดอัตโนมัติไปแล้วหลังจ่ายเงิน)
```sql
INSERT INTO orders (table_id, order_type) VALUES (2, 'dine_in');
```
> "ถึงจะ INSERT ตรงเข้าฐานข้อมูลโดยไม่ผ่านเว็บ trigger `trg_orders_bi_table_open` ก็ปฏิเสธด้วย SIGNAL เพราะโต๊ะยังไม่เปิด"

**Trigger ตัวที่ 1: ตัดสต็อก**
```sql
SELECT ingredient_name, quantity_in_stock FROM ingredient WHERE ingredient_name IN ('หมูสับ','ไข่ไก่');
```
> "ตอนสั่งกะเพรา 2 จาน trigger `trg_order_item_bi_stock` อ่านสูตรจาก `menu_item_ingredient` แล้วตัดหมูสับ 200 กรัม ไข่ 2 ฟองให้เอง
> ถ้าวัตถุดิบไม่พอ เช่น สั่งผัดไทย 99 จาน จะ SIGNAL ยกเลิกทั้งออเดอร์"
→ (ให้คนที่ 2 ลองสั่ง × 99 บนเว็บ) ขึ้น "Out of stock"

**Trigger ตัวที่ 3: หลังเปลี่ยนสถานะ**
```sql
SELECT table_id, status FROM dining_table;
```
> "`trg_orders_au_status` ทำ 2 อย่าง: ยกเลิกออเดอร์แล้วคืนสต็อก และชำระเงินครบแล้วปิดโต๊ะกลับเป็น available อัตโนมัติ เมื่อกี้แคชเชียร์รับเงินโต๊ะ 2 จึงว่างแล้ว"

**Stored procedure**
```sql
CALL sp_sales_summary(CURDATE());
```
> "`sp_sales_summary` สรุปยอดขายของวันที่ส่งเข้าไป ได้แก่ รายได้ ออเดอร์ที่จ่ายแล้ว ยอดเฉลี่ย ยกเลิก และจำนวนจาน แดชบอร์ดเรียก procedure นี้ทุกครั้ง"
→ เปิดแดชบอร์ด ชี้ตัวเลขที่ตรงกัน + ข้อความ "คำนวณโดย stored procedure" → เปลี่ยนวันที่

**Security** **[จอ: `orderModel.js`, `.env.example`, `errorHandler.js`]**
> "ด้านความปลอดภัย:
> 1. **Parameterized query:** ทุก query ใช้ `?` ไม่ต่อ string ลองพิมพ์ `admin' OR '1'='1` ที่หน้า login ก็เข้าไม่ได้
> 2. **ไม่ hardcode ค่าลับ:** รหัสฐานข้อมูลและ JWT secret อยู่ใน `.env` ซึ่งไม่ถูก commit ขึ้น GitHub
> 3. **Error ไม่หลุด:** error ที่ไม่คาดคิดตอบแค่ 'Internal server error' รายละเอียดอยู่ใน log ของ server เท่านั้น
> 4. **Hash รหัสผ่าน:** เก็บเป็น bcrypt hash (เปิด `SELECT username, password_hash FROM staff;` ให้ดู)"

**[จอ: terminal `npm run test:e2e`]**
> "สุดท้ายเรามี test อัตโนมัติ 55 ข้อ ยิง API จริงครอบคลุมทุก role, trigger, CRUD และ procedure ผ่านทั้งหมด แล้วคืนข้อมูลเดิมให้ ขอบคุณครับ"

## เตรียมตอบคำถาม (ทุกคนอ่าน)

| คำถามที่น่าจะโดน | คำตอบสั้น |
|---|---|
| ทำไมมี 7 ตาราง ไม่ใช่ 11 แบบที่ออกแบบตอนแรก | ตัดตารางที่ไม่ได้ใช้ (`table_session`), รวม 1:1 (`employee`+`sys_user` → `staff`) และตัดระบบจองที่ไม่ใช่ flow หลักของร้าน |
| role เก็บยังไง ทำไมไม่แยกตาราง | ENUM ใน `staff.role` มี 4 ค่าและคนหนึ่งมี role เดียว MySQL บังคับค่าได้เลยโดยไม่ต้อง JOIN สิทธิ์ของแต่ละ role อยู่ใน `permissions.js` |
| ถ้ายิง API ตรงข้ามหน้าเว็บได้ไหม | ไม่ได้ backend ตรวจ JWT + role ทุก request (401 ไม่ login / 403 ไม่มีสิทธิ์ / 409 ข้ามขั้น) |
| ลูกค้าสั่งจากบ้านได้ไหม | ไม่ได้ สั่งได้เฉพาะโต๊ะที่พนักงานเปิด ตรวจ 2 ชั้นคือ backend และ trigger และจ่ายเงินแล้วโต๊ะปิดเอง |
| ทำไมเก็บ `subtotal` ใน `order_item` ทั้งที่คำนวณจากราคาได้ | ราคาเมนูเปลี่ยนได้ บิลเก่าต้องเป็นราคา ณ ตอนสั่ง |
| ทำไมลบเมนูบางตัวไม่ได้ | FK `ON DELETE RESTRICT` จาก `order_item` กันประวัติออเดอร์หาย ระบบจึงซ่อน (`is_active = 0`) แทน |
| ถ้าสองคนกดพร้อมกันล่ะ | สั่งอาหาร/จ่ายเงินอยู่ใน transaction + `SELECT ... FOR UPDATE` และเปลี่ยนสถานะแบบ `WHERE status = เดิม` ถ้ามีคนเปลี่ยนไปก่อนได้ 409 |
| จ่ายด้วยบัตร ทำไมไม่มีช่องกรอกเลขบัตร | รูดที่เครื่อง EDC ของธนาคาร ระบบแค่บันทึกว่าจ่ายด้วยบัตร ไม่เก็บเลขบัตรเพื่อความปลอดภัย |
| trigger กับโค้ดตรวจซ้ำกันทำไม (โต๊ะเปิด) | backend ให้ข้อความ error ที่อ่านง่าย trigger กันที่ระดับฐานข้อมูลแม้มีคน INSERT ตรง |
| ทำไม procedure บนเว็บออนไลน์ไม่ทำงาน | เว็บออนไลน์ใช้ TiDB Cloud (ฟรี) ซึ่งไม่รองรับ trigger/procedure backend จึงมี query สำรอง และ demo ส่วนนี้ด้วย MySQL ในเครื่อง |
| password hash ทำยังไง | bcrypt (cost 10) ตอน login ใช้ `bcrypt.compare` ไม่เคยเก็บรหัสจริง |
